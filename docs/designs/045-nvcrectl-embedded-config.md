# ADR-045: Embedded Config and Go Client Apply in nvcrectl

## Context

`nvcrectl setup init` installs NVCRE by shelling out to `kubectl apply -k` with remote kustomize URLs pointing at the Git repository:

```
https://github.com/NVIDIA/cluster-readiness-engine/releases/download/<version>/crds.yaml
```

The `version` variable is injected at build time via `git describe --tags --always --dirty`. This design has three problems:

1. **Broken in non-release builds.** `git describe` produces refs like `1.13.0-dirty` or `dev` that don't exist as Git refs. Any build from a non-tagged commit fails at install time.
2. **Requires kubectl.** Users must have kubectl installed and in PATH, even though nvcrectl already has a full Go Kubernetes client.
3. **Requires network access.** nvcrectl must reach `github.com` at install time to fetch manifests. Air-gapped environments cannot use `setup init`.

The catalog (benchmark configurations) is already embedded into the binary via `go:embed` and works reliably offline. The setup manifests should follow the same pattern.

## Decision

1. **Embed** all NVCRE manifests (CRDs, controller stack, LogProfiles) into the nvcrectl binary via `go:embed`.
2. **Apply via Go client** using controller-runtime server-side apply on `unstructured.Unstructured` — no kubectl needed for NVCRE resources.
3. **Keep kubectl** only for the `[deps]` phase (Kubeflow Trainer), which is fetched from a remote GitHub kustomize URL.
4. **Add `--version` flag** to `setup init` and `setup reset` as an override to fetch from a remote URL instead of using embedded manifests (for installing a different version than the binary).
5. **Add a Makefile version guard** to prevent release artifacts from being built with dirty or dev versions.

### Embedded Files

Generated by the `embed-nvcrectl` Makefile target, committed to `.gitignore`:

```
pkg/setup/embedded/
├── crds/                   # 7 CRD YAML files from config/crd/bases/
├── logprofiles/            # 4 LogProfile YAML files from config/logprofiles/
└── controller.yaml         # Pre-rendered kustomize build of config/default
```

### Apply/Delete Functions

New core functions replace the kubectl-based approach:

- `applyManifests(ctx, c, yamlBytes, out)` — splits multi-doc YAML by `---`, decodes each into `unstructured.Unstructured`, applies via `client.Patch(ctx, obj, client.Apply, client.FieldOwner("nvcrectl"), client.ForceOwnership)`.
- `deleteManifests(ctx, c, yamlBytes, out)` — same decode path, `client.Delete` with ignore-not-found.
- `applyEmbeddedDir(ctx, c, fsys, dir, out)` — reads all YAML files from an `embed.FS` directory, concatenates, calls `applyManifests`.
- `deleteEmbeddedDir(ctx, c, fsys, dir, out)` — same, calls `deleteManifests`.
- `patchControllerImage(yamlBytes, newImage, imagePullSecret)` — parses the pre-rendered controller YAML, finds the Deployment, replaces `.spec.template.spec.containers[0].image`, optionally patches `imagePullSecrets`.

### Modified runInit Flow (default embedded path)

```
1. [preflight]    getClusterInfo (no longer requires kubectl for NVCRE phases)
2. [deps]         runKubectlApply (Kubeflow Trainer from GitHub — unchanged)
3. [crds]         applyEmbeddedDir(ctx, c, embeddedCRDs, "embedded/crds", out)
4. [controller]   patchControllerImage(embeddedController, image, pullSecret)
                  → applyManifests(ctx, c, patched, out)
5. [logprofiles]  applyEmbeddedDir(ctx, c, embeddedLogProfiles, "embedded/logprofiles", out)
```

### Modified runReset Flow (default embedded path)

```
1. [logprofiles]  deleteEmbeddedDir(ctx, c, embeddedLogProfiles, "embedded/logprofiles", out)
2. [controller]   deleteManifests(ctx, c, embeddedController, out)
3. [crds]         deleteEmbeddedDir(ctx, c, embeddedCRDs, "embedded/crds", out)
4. [deps]         runKubectlDelete (Kubeflow Trainer from GitHub — unchanged)
```

### `--version` Flag

When `--version` is set on `init` or `reset`, nvcrectl falls back to the remote kustomize URL approach (the current behavior) using the specified version as the Git ref. This supports installing a different version than what's embedded in the binary. kubectl is required in this mode.

### Version Guard

A new `check-clean-version` Makefile target blocks release artifact builds when VERSION contains `dirty`, `dev`, or an intermediate commit suffix (`-N-gXXX`). Added as a dependency to `docker-push`, `docker-buildx`, and `build-nvcrectl-cross`.

### imagePullSecret Flow Fix

`runCertificationLifecycle` calls `runInit("", "", "", true, ...)` with empty imagePullSecret. When `--image-pull-secret` is provided to `certification run`, the NGC API key should also flow to `runInit` so the controller Deployment can pull from `nvcr.io`. The fix:

1. Create the `dockerconfigjson` secret in the `nvcre` namespace before `runInit`.
2. Pass the secret **name** to `runInit` (which expects a name, not a raw key).
3. Also create the same secret in the certification target namespace for workload pods (existing behavior).

### probeExistingComponents Migration

Replace `probeKubectl` (shells out to kubectl) with Go client probes using `c.Get(ctx, ...)` on the relevant resources. Fix the controller namespace from `cre-system` to `nvcre`.

## Rationale

- **Embedded manifests** eliminate the version mismatch problem. The binary always carries the manifests for its own version.
- **Go client apply** removes the kubectl dependency for NVCRE phases and enables air-gapped operation.
- **Server-side apply** with `FieldOwner("nvcrectl")` provides the same conflict detection as `kubectl apply --server-side`.
- **Kubeflow Trainer stays remote** because it is an external dependency with its own release cadence. Embedding it would require updating nvcrectl for every Kubeflow release.
- **Version guard** catches the dirty/dev problem at build time rather than at install time.
- **`--version` override** provides an escape hatch for operators who need to install a specific version that differs from the binary.

## Consequences

### Positive

- `nvcrectl setup init` works offline (except for the `[deps]` phase).
- No kubectl needed for CRDs, controller, or LogProfiles.
- Build-time version mismatches are caught by the version guard.
- Binary size increases by ~200KB (embedded YAML).

### Negative

- Embedded files must be regenerated when CRDs or controller config change (`make embed-nvcrectl`). The `build-nvcrectl` target depends on `embed-nvcrectl` to automate this.
- The `[deps]` phase (Kubeflow Trainer) still requires kubectl and network access.

## Alternatives Considered

1. **Fix the version only**: Pin VERSION in CI and keep kubectl. Doesn't solve the kubectl/network dependency.
2. **Embed everything including Kubeflow**: Couples nvcrectl releases to Kubeflow releases. Rejected.
3. **Extract to temp files and pipe to kubectl**: Removes the remote URL problem but still requires kubectl. Rejected in favor of the Go client.
